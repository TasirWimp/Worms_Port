## Purpose

WP-015D2H proved that one policy-visible source class can contain transitions
with different selected actions or different rich successors. A subsequent
read-only comparison with the recent CRPM candidate-mathematical-spine work
showed that this statement combines several target-relative questions:

1. does the declared policy select the same action;
2. under a matched action, does the visible gameplay successor agree;
3. does the completed-turn-excluding tactical recurrence carrier agree;
4. does the exact analytical carrier agree; and
5. does the terminal relation agree?

These obligations must not be compressed into one generic alias verdict. The
same review also separates public carrier formation from its later transport.
F4 supplies a concrete local pressure case: `prepare_spoolburst` publicly forms
one Spun Cocoon hit, but the response route after formation may depend on actor
phase, policy pairing, and action order.

This package therefore reconstructs the existing Cocoon voyages at production
spawn 640 and classifies their target-relative descent and ordered response
relations. It does not add, tune, or recommend a gameplay mechanic.

## Target-typed descent audit

For each F4 and I2 policy-visible alias witness, retain the exact left/right
source references and classify it through these separate targets.

### Policy-selection target

Ask whether the registered policy maps equal policy-visible sources to the
same selected action. A split here is a policy-selection descent defect. It is
not evidence that one matched gameplay action has different effects.

### Matched-action visible target

Only when both sides select the same exact action, compare the next visible
carrier:

- active actor;
- player and Loomkeeper positions;
- separation; and
- both Stitching values.

A split here is an exact finite witness of failed dynamic descent for that
declared action and visible target. Attribute Cocoon only when the authoritative
trace and source/target Cocoon fields prove the absorption relation.

### Tactical-recurrence target

Compare the existing completed-turn-excluding recurrence keys. A split with an
equal visible successor is recurrence-support residue, not immediate visible
damage divergence.

### Exact-carrier and terminal targets

Keep exact carrier and terminal-relation equality separate. An exact carrier
split caused only by completed-turn progress must not be promoted into a
tactical difference. Conversely, terminal equality must not erase a visible or
recurrence-support split.

The expected exhaustive representative partition per config is:

- `policy_selection_split`;
- `matched_action_visible_descent_defect`;
- `matched_action_recurrence_support_split`; or
- `matched_action_exact_time_residue`.

Every one of the 68 D2H policy-visible witness pairs must occupy exactly one
class. Any overlap, omission, detached witness, or unrecognized cause fails
closed.

## Cocoon formation and voyage records

Each existing `prepare_spoolburst` transition forms one voyage. Preserve:

- config, match, policy pair, first actor, mirror, path prefix, and formation
  edge reference;
- preparer and whether the preparer is first or second in phase order;
- formation source/target carrier and digests;
- immediate opponent response edge, action, damage, Cocoon effect, and support
  residue;
- the preparer's following resolution edge when present;
- disposition:
  `released_spoolburst | unwoven | terminal_before_resolution | unresolved`;
- whether Cocoon was consumed by Needlepoint, consumed by Spoolburst, cleared
  by Unweave, bypassed by Threadball, or expired on the preparer's resolution;
- position, Stitching, Escape-Slack, preparation, and Cocoon deltas;
- recurrence and terminal relations; and
- exact re-entry references to the D2H raw transitions.

The audit must reject a preparation without a recoverable immediate response,
ambiguous transition ordering, inconsistent actor alternation, a detached
resolution, or a Cocoon effect not supported by the authoritative trace.

## Ordered-route comparison

Aggregate voyage records separately by config and preparer phase. Compare:

- formation count;
- immediate response-action family;
- Cocoon consumption/clearance route;
- release versus Unweave disposition;
- damage and resource residue; and
- terminal/recurrence outcome.

The known read-only trigger is that formation and Unweave totals appear
phase-symmetric while one response family differs: some routes cast a prepared
Spoolburst into a first actor's Cocoon, whereas the corresponding second-actor
phase routes prepare instead. The implementation must reconstruct exact route
records and policy/mirror support before retaining this as an
`ordered_response_split`.

This label does not claim a mathematical noncommutative operator, causal
initiative repair, independent evidence, or a gameplay recommendation. If no
recoverable paired support exists, return the route difference as an aggregate
residue only.
